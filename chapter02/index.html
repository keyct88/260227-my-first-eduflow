    Chapter 02. 처음 만나는 데이터 분석 프로젝트¶

    — 교과서 예시로 전체 흐름 훑어보기¶

    🎯 이 장의 학습 목표¶

    • 데이터 분석 프로젝트의 6단계 절차를 순서대로 말할 수 있습니다.
    • 각 단계에서 어떤 활동이 이루어지는지 설명할 수 있습니다.
    • 좋은 보고서와 부족한 보고서의 차이를 구분할 수 있습니다.

    ⏱️ 예상 학습 시간: 약 40분

    📚 미리 알아야 할 것¶

    지난 Chapter 01에서 우리는 "데이터 분석이 왜 필요한가"를 배웠어요. 데이터가 넘쳐나는 세상에서 의미 있는 정보를 뽑아내는 능력이 중요하다는 것, 기억하시죠? 😊

    이번 장에서는 한 발짝 더 나아가서, 실제로 데이터 분석이 어떤 순서로 이루어지는지 전체 흐름을 한 번 훑어볼 거예요.

    📚 핵심 개념¶

    개념 1: 데이터 분석은 요리와 같아요 🍳¶

    데이터 분석은 마치 처음 보는 레시피로 요리하는 것과 같아요.

    재료를 사기 전에 뭘 만들지 정하고 → 필요한 재료를 사고 → 다듬고 → 조리하고 → 맛을 보고 → 손님에게 차려내는 것처럼, 데이터 분석도 정해진 순서가 있어요.

    이 순서를 데이터 분석 6단계 절차라고 합니다.

    flowchart LR A["❶ 문제 정의\n무엇을 알고 싶은가?"] --> B["❷ 데이터 수집\n필요한 데이터 모으기"] B --> C["❸ 데이터 전처리\n데이터 다듬기"] C --> D["❹ 시각화\n그래프로 표현"] D --> E["❺ 분석 해석\n패턴 찾기"] E --> F["❻ 결론 도출\n해결책 제안"]

    각 단계를 교과서 예시를 통해 하나씩 살펴볼게요!

    💡 잠깐! 처음 보면 6단계가 많아 보일 수 있어요. 하지만 곧 "아, 당연한 순서구나!" 하는 느낌이 올 거예요. 천천히 따라와 주세요 😊

    개념 2: 교과서 예시 — "학교 주변 교통사고 분석"¶

    어떤 학생이 이런 생각을 했어요.

    "우리 학교 앞 사거리에서 사고가 자주 나는 것 같은데… 데이터로 확인해볼 수 있을까?"

    이 질문 하나가 데이터 분석 프로젝트의 시작이에요! 6단계를 이 예시에 적용해볼게요.

    ❶ 문제 정의 — "무엇을 알고 싶은가?"

    • 활동: 분석의 목적을 구체적으로 씁니다.
    • 예시: "우리 학교 주변 300m 이내에서 최근 3년간 발생한 교통사고의 원인과 패턴을 분석한다."

    ✅ 좋은 문제 정의는 구체적이에요. "교통사고를 분석한다"는 너무 막연하고, "어디서, 언제, 무엇을"이 담겨야 해요!

    ❷ 데이터 수집 — "필요한 데이터 모으기"

    • 활동: 분석에 필요한 데이터를 찾아서 가져옵니다.
    • 예시: 경찰청 교통사고 공공데이터, 구청 도로 현황 자료 다운로드

    📌 공공데이터란? 정부나 공공기관이 누구나 무료로 쓸 수 있도록 공개한 데이터예요. data.go.kr 에서 찾을 수 있어요!

    ❸ 데이터 전처리 — "데이터 다듬기"

    • 활동: 빠진 값, 잘못된 값을 정리합니다.
    • 예시: 날짜 형식이 제각각인 것 통일하기, 주소가 비어있는 행 제거하기

    전처리는 마치 요리 전에 채소를 다듬는 것과 같아요. 귀찮지만 꼭 필요해요! 🥦

    ❹ 시각화 — "그래프로 표현"

    • 활동: 정리된 데이터를 그래프나 지도로 표현합니다.
    • 예시: 시간대별 사고 건수 막대그래프, 사고 다발 지점 지도 표시

    ❺ 데이터 분석 — "패턴 찾기"

    • 활동: 시각화된 데이터를 통해 의미 있는 패턴과 인사이트를 발견합니다.
    • 예시: 오전 8시~9시에 사고가 가장 많다 / 비 오는 날 사고 건수가 1.8배 증가

    ❻ 결론 도출

    활동: 분석 결과를 바탕으로 의미를 확장하거나 제안을 합니다.

    결론 도출은 데이터(사실)로 부터 나와야 합니다. 아래와 같이 다양한 방식으로 접근할 수 있습니다.

    • 해결책 제안
      예시: "등교 시간대(8~9시)에 교통안전 도우미 배치 및 신호 시간 조정을 건의합니다."
    • 실생활 연결
      예시: "급식 만족도 분석 결과를 반영해 학생들이 선호하는 메뉴를 급식 주간에 포함하면 만족도를 높일 수 있습니다."
    • 사회적·과학적 현상 연결
      예시: "교통사고 연령대별 분석은 고령 운전자 안전 정책과도 관련이 있으며, 고령화 사회에서 중요한 시사점을 줍니다."
    • 한계점 작성
      예시: "이번 분석은 특정 기간의 데이터에 한정되므로, 장기적 추세를 확인하기 위해 연도별 데이터를 추가로 수집할 필요가 있습니다."(연구적 확장 제안)
      예시: "설문 데이터는 응답자의 주관적 판단에 의존하므로, 객관적 지표와 함께 분석하는 것이 필요합니다."(비판적 성찰)

    💡 잠깐! 여기까지 6단계 흐름이 이해되셨나요? 어렵게 느껴져도 괜찮아요. 아래 활동을 통해 한 번 더 정리해봐요!

    🔨 따라하기 — 빈칸으로 흐름 정리하기¶

    아래 각 상황이 6단계 중 어느 단계인지 번호를 써보세요!

    상황 A. 수집한 데이터에서 날짜가 없는 행을 삭제했다. → ( ) 단계

    상황 B. "우리 동네에서 쓰레기 무단투기가 가장 많은 장소는 어디인가?"라고 질문했다. → ( ) 단계

    상황 C. 시간대별 무단투기 건수를 막대그래프로 나타냈다. → ( ) 단계

    상황 D. 구청 민원 데이터를 공공데이터 포털에서 내려받았다. → ( ) 단계

    ✅ 정답 확인 - **상황 A** → ❸ 데이터 전처리 - **상황 B** → ❶ 문제 정의 - **상황 C** → ❹ 시각화 - **상황 D** → ❷ 데이터 수집 모두 맞으셨나요? 헷갈렸다면 위 6단계 설명을 한 번 더 읽어보세요! 😊

    ⚠️ 주의할 점¶

    주의 1. 결론은 데이터에서 나와야 해요

    보고서에서 가장 많이 하는 실수는 데이터와 무관한 결론을 내리는 거예요.

    • ❌ 부족한 예: "사고가 많으니까 학교 앞 도로를 폐쇄해야 합니다." ← 데이터 근거 없음
    • ✅ 좋은 예: "8~9시 사고가 전체의 42%이므로 해당 시간 신호 주기를 조정해야 합니다." ← 데이터 근거 있음

    주의 2. 문제 정의가 흐릿하면 나머지 단계가 다 흔들려요

    ❶번 단계를 대충 넘기면 어떤 데이터를 모아야 할지, 무엇을 분석해야 할지 방향을 잃어버려요. 시작할 때 "무엇을, 왜, 어떤 범위에서" 를 명확히 적어두는 습관을 들여요!

    ✅ 점검하기¶

    1. 데이터 분석 6단계를 순서대로 말할 수 있나요?
    정답 확인 ❶ 문제 정의 → ❷ 데이터 수집 → ❸ 데이터 전처리 → ❹ 시각화 → ❺ 데이터 분석 → ❻ 결론 도출
    1. "비 오는 날 교통사고가 많다"는 사실을 발견한 것은 몇 번째 단계인가요?
    정답 확인 ❺ 데이터 분석 단계예요. 시각화한 데이터에서 패턴과 인사이트를 찾아내는 활동이에요.
    1. 좋은 보고서의 결론이 갖춰야 할 조건은 무엇인가요?
    정답 확인 결론은 반드시 데이터 분석 결과를 근거로 해야 해요. "데이터에 따르면 ~이므로, ~를 제안합니다"처럼 근거와 제안이 연결되어야 해요.

    📌 이 장의 핵심 정리¶

    • ✅ 데이터 분석은 문제 정의 → 수집 → 전처리 → 시각화 → 분석 → 결론의 6단계로 진행돼요.
    • ✅ 각 단계는 서로 연결되어 있고, 앞 단계가 탄탄해야 뒤 단계가 잘 됩니다.
    • ✅ 좋은 보고서는 데이터에 근거한 결론을 담고 있어요.
